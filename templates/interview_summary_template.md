# 面试表达版总结模板

## 项目背景

我选择分析（游戏名称），因为它属于（游戏类型），与目标岗位中的（数据分析 / 游戏运营 / 产品分析）能力高度相关。我的目标不是写主观体验，而是用结构化方法拆解游戏的用户需求、核心循环、功能模块、指标体系和优化空间。

## 我的分析目标

- 判断游戏如何通过核心玩法满足用户需求。
- 拆解关键模块对留存、活跃、付费、广告和社交传播的作用。
- 设计可用于真实业务分析的指标体系。
- 提出能通过 A/B Test 或数据分析验证的优化建议。

## 我的拆解方法

我使用了“用户路径 + 功能模块 + 数据指标 + 模块耦合 + 优化实验”的方法：

1. 先分析目标用户和核心使用场景。
2. 再拆解核心玩法循环和成长路径。
3. 然后逐个分析功能模块为什么存在、服务谁、影响什么指标。
4. 最后提出指标异常解释和可验证的优化方案。

## 我的核心发现

- 发现 1：（例如新手引导对 D1 留存影响最大，但强制步骤可能过长）
- 发现 2：（例如任务系统承担日常活跃目标，但奖励重复可能造成疲劳）
- 发现 3：（例如广告激励可以提升非付费收入，但需要控制频率避免伤害留存）

## 我的指标体系设计

我将指标分为新增、活跃、留存、付费、转化、关卡、经济、广告、社交、用户分层和异常监控几类。每个指标不仅定义计算口径，还说明它适用哪个模块、业务意义、升降原因和优化方向。

## 我的优化建议

我的优化建议遵循“问题 -> 证据 -> 影响指标 -> 方案 -> 风险 -> A/B Test”的结构，而不是只给主观建议。例如：

- 对新手引导，优化目标是提升新手完成率和 D1 留存。
- 对任务系统，优化目标是提升任务完成率、启动次数和 D7 留存。
- 对广告系统，优化目标是在不降低广告后留存的前提下提升广告收入。

## 如果有数据，我会如何验证

- 用漏斗分析定位路径流失点。
- 用留存分群比较参与模块和未参与模块用户。
- 用用户分层观察新用户、活跃用户、付费用户和沉默用户差异。
- 用 A/B Test 验证入口、奖励、频率、文案和触发时机。
- 用护栏指标避免短期收入提升伤害长期体验。

## 这个项目体现的能力

- 产品理解：能从用户需求和核心玩法解释设计动机。
- 数据分析：能将模块拆解为指标口径和验证方法。
- 游戏运营：能围绕留存、活跃、付费、广告和活动提出策略。
- 用户体验研究：能识别路径阻力、用户心理和流失原因。
- 工程能力：能用结构化 YAML 和 Python 自动生成 Markdown 报告。
