# 游戏产品拆解报告模板

> 使用方式：将括号中的提示替换为你对具体游戏的观察、判断、数据假设和验证方案。不要只写主观感受，尽量把每个判断落到指标、用户分层或实验设计。

## 1. 产品基础信息

| 字段 | 内容 |
| --- | --- |
| 产品名称 | （游戏名称） |
| 游戏类型 | （休闲消除 / MMORPG / 卡牌 / SLG / Roguelike / 派对 / 竞技等） |
| 目标用户 | （核心用户、泛用户、付费用户、社交用户等） |
| 核心玩法 | （一句话描述用户反复进行的主要行为） |
| 商业化模式 | （内购 / 广告 / 订阅 / 战令 / 皮肤 / 混合变现等） |
| 体验版本 | （版本号或体验渠道） |
| 体验时间 | （日期区间） |
| 分析目标 | （为了验证什么问题，服务什么岗位能力展示） |

## 2. 产品定位分析

### 用户需求

- 显性需求：（用户主动说得出来的需求，例如放松、竞技、收集、社交）
- 隐性需求：（情绪价值、身份表达、成就感、陪伴、逃避压力等）
- 高频场景：（通勤、睡前、碎片时间、长线沉浸、好友组局等）

### 使用场景

| 场景 | 用户状态 | 产品需要提供的价值 | 可能关注指标 |
| --- | --- | --- | --- |
| （场景） | （心理 / 时间 /设备状态） | （即时反馈 / 低门槛 / 深度目标等） | （启动次数、单次时长、关卡完成率等） |

### 产品卖点

- 核心卖点：（最能让用户留下来的特点）
- 差异化竞争点：（相比同类产品更强或更明确的部分）
- 用户为什么要玩：（需求、情绪、社交、成长、奖励中的关键驱动）

### 目标用户画像

| 用户分层 | 用户特征 | 主要需求 | 关键阻力 | 需要关注的指标 |
| --- | --- | --- | --- | --- |
| 新用户 | （首次接触） | （快速理解和获得反馈） | （规则复杂、加载慢、目标不清） | 新手完成率、D1 留存 |
| 活跃用户 | （稳定回访） | （日常目标和成长） | （重复感、奖励疲劳） | DAU、任务完成率、D7 留存 |
| 付费用户 | （愿意为效率或表达付费） | （效率、稀缺、身份） | （价格不合理、付费压迫） | 付费率、ARPPU、复购率 |

## 3. 核心玩法拆解

### 核心循环

用一句话描述：

> 用户通过（行为）获得（反馈 / 奖励），再使用奖励推动（成长 / 解锁 / 社交 / 付费），从而进入下一轮行为。

推荐拆成：

1. 进入目标：（用户打开游戏后首先被引导去做什么）
2. 执行行为：（核心操作或策略选择）
3. 即时反馈：（音效、动画、分数、胜负、掉落）
4. 奖励获得：（资源、经验、道具、关卡进度）
5. 成长推进：（等级、装备、角色、地图、图鉴）
6. 下一目标：（任务、活动、排行榜、社交邀请）

### 完整用户路径

| 步骤 | 用户行为 | 系统反馈 | 用户心理 | 可能流失点 | 关键指标 |
| --- | --- | --- | --- | --- | --- |
| 1 | （进入游戏） | （加载 / 首屏 / 新手引导） | （好奇 / 观望） | （加载慢、信息过载） | 激活率、首局开始率 |

### 核心爽点

- 操作爽点：（操作是否低成本、反馈是否明确）
- 策略爽点：（是否有选择空间和可成长空间）
- 成长爽点：（奖励是否能转化为可感知进步）
- 社交爽点：（是否能炫耀、协作、竞争或邀请）

### 成长路径

- 短期目标：（首局胜利、首个奖励、首个装扮）
- 中期目标：（章节推进、战令、活动、角色培养）
- 长期目标：（收藏、排行榜、公会、赛季、稀有资产）

### 目标感、反馈感、成就感

- 目标感：游戏如何告诉用户“下一步该做什么”？
- 反馈感：游戏如何让用户知道“我刚才做得不错”？
- 成就感：游戏如何让用户觉得“我变强了 / 我拥有了 / 我被看见了”？
